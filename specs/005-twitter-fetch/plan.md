# Implementation Plan: Twitter Data Fetch (Minimum Viable)

**Branch**: `005-twitter-fetch` | **Date**: 2026-04-13 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/005-twitter-fetch/spec.md`

## Summary

Implement the first real batch job: periodically fetch recent tweets from registered store Twitter accounts, filter by oripa keywords, and save new tweets as unprocessed records in DynamoDB. The Lambda function already exists and has IAM access to all required tables; this feature wires it up with the Twitter API v2 Recent Search endpoint and adds an EventBridge hourly schedule.

---

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 22 LTS (Lambda runtime: `nodejs22.x`)
**Primary Dependencies**: `twitter-api-v2` (Twitter API v2 client), `@aws-sdk/lib-dynamodb` (DynamoDB DocumentClient), `ulid` (internal ID generation)
**Storage**: DynamoDB — `${DEPLOY_ENV}-stores` (read), `${DEPLOY_ENV}-tweets` (write)
**Testing**: `vitest` (unit); manual Lambda invocation (integration)
**Target Platform**: AWS Lambda (ARM64 or x86_64, 5-minute timeout)
**Project Type**: Serverless batch job (Lambda + EventBridge)
**Performance Goals**: Process up to 50 stores within 5 minutes per run
**Constraints**: Twitter API v2 Free tier — 500k tweet reads/month; 15 req/15 min per endpoint per app
**Scale/Scope**: ~10–50 stores initially; hourly schedule

## Implementation Phases

### Phase A: Schema + Dependencies (no runtime impact)

1. Add `lastFetchedTweetId?: string` to `StoreItem` in `packages/db/schema/index.ts`
2. Add `twitter-api-v2` to `apps/batch/package.json` via `pnpm --filter @oripa-now/batch add twitter-api-v2`
3. Store Twitter Bearer token in SSM: `/oripa-now/${deployEnv}/TWITTER_BEARER_TOKEN`

### Phase B: Batch Logic

4. Implement `apps/batch/src/fetch.ts`:
   - `fetchTweetsForStore(client: TwitterApi, store: StoreItem, sinceId?: string): Promise<TweetV2[]>`
   - Query: `from:${store.twitterUsername} (オリパ OR oripa) -is:retweet`
   - Returns up to 100 tweets (one page — sufficient for hourly cadence)

5. Implement `apps/batch/src/save.ts`:
   - `saveTweets(docClient, tweets: TweetV2[], store: StoreItem): Promise<number>` — writes new `TweetItem` records; returns count written
   - `updateLastFetchedTweetId(docClient, storeId: string, tweetId: string): Promise<void>` — `UpdateItem` on stores table

6. Update `apps/batch/src/index.ts`:
   - Replace health-check handler with `FetchRunResult` handler
   - Read all active stores (`isActive = true`) from stores table
   - For each store: `fetchTweetsForStore` → `saveTweets` → `updateLastFetchedTweetId`
   - Wrap per-store logic in `try/catch`; accumulate errors
   - Return `FetchRunResult` summary

### Phase C: Infrastructure

7. Update `infra/cdk/lib/batch-stack.ts`:
   - Increase Lambda timeout: `cdk.Duration.minutes(5)`
   - Add SSM parameter read for `TWITTER_BEARER_TOKEN` and inject as env var
   - Add EventBridge rule: `events.Rule` with `schedule: events.Schedule.rate(cdk.Duration.hours(1))`

### Phase D: Verification

8. Manual `aws lambda invoke` — verify `tweetsWritten > 0` and `errors: []`
9. Check DynamoDB tweets table for new unprocessed records
10. Check stores table that `lastFetchedTweetId` is updated
