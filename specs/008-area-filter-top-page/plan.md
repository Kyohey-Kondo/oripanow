# Implementation Plan: Area Filter on Top Page

**Branch**: `008-area-filter-top-page` | **Date**: 2026-04-14 | **Spec**: [spec.md](spec.md)

## Summary

Add an area filter bar to the top page so users can narrow posts to a single area via `?area=` query param. Two files change: `apps/web/lib/posts.ts` gains an optional `area?` param, and `apps/web/app/page.tsx` reads `searchParams`, renders a filter nav, and passes the selection downstream.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 22 LTS  
**Primary Dependencies**: Next.js 15 (App Router, `force-dynamic`), `@aws-sdk/lib-dynamodb`  
**Storage**: DynamoDB via existing `queryRecentOnSalePostsByArea`  
**Testing**: Vitest  
**Target Platform**: Web (deployed via Lambda Web Adapter + CloudFront)  
**Project Type**: web-service  
**Performance Goals**: No change — filter is applied before DynamoDB query, reducing work  
**Constraints**: No `"use client"` allowed; must remain a Server Component  
**Scale/Scope**: 4 areas, ~50 posts max

## Constitution Check

## Implementation Details

### `apps/web/lib/posts.ts`

Add `area?: string` to `getTodayOnSalePosts`:

```ts
const areasToQuery = area && AREAS.includes(area as typeof AREAS[number])
  ? [area as typeof AREAS[number]]
  : AREAS;
const results = await Promise.all(
  areasToQuery.map(a => queryRecentOnSalePostsByArea(client, TABLE_NAME, a))
);
```

### `apps/web/app/page.tsx`

1. Destructure `searchParams` as `Promise<{ area?: string }>` (Next.js 15)
2. Define `AREA_LABELS`:
   ```ts
   const AREA_LABELS: Record<string, string> = {
     akihabara:   '秋葉原',
     kawagoe:     '川越',
     omiya:       '大宮',
     urawamisono: '浦和美園',
   };
   ```
3. Render `<nav>` above the table:
   - "すべて" → `href="/"`, active when `area` is undefined
   - Each area key → `href={`/?area=${key}`}`, active when `area === key`
   - Active style: `background: #333; color: #fff`; inactive: `background: #eee; color: #333`
4. Pass `area` to `getTodayOnSalePosts(area)`
