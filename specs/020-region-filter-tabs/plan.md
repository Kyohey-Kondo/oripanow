# Implementation Plan: Region Filter Tabs

**Branch**: `020-region-filter-tabs` | **Date**: 2026-05-14 | **Spec**: [spec.md](spec.md)

## Summary

Add a two-tier region/area navigation to the oripa listing page. Tier-1 lets users select 全国 / 関東 / 関西; Tier-2 then shows only the area tabs belonging to the selected region. No DynamoDB schema changes — UI and routing layer only.

## Implementation Steps

### Step 1 — `apps/web/lib/regions.ts` (new file)

Define `REGIONS` array and two helpers:
- `getRegionForArea(area: string): RegionKey | null`
- `getAreasForRegion(region: string | null | undefined): string[]` — returns region's areas, or all AREAS if null

### Step 2 — `apps/web/lib/posts.ts`

Extend `getTodayOnSalePosts`:
```ts
export async function getTodayOnSalePosts(
  area?: string,
  regionAreas?: string[],
): Promise<OripaPostSummary[]>
```
Logic: `area` set → query `[area]`; else `regionAreas` set → query those; else query all `AREAS`.

### Step 3 — `apps/web/app/oripa/page.tsx`

1. Add `region` to `searchParams` type
2. Resolve visible area tabs: `getAreasForRegion(region)` → subset of `AREA_LABELS_MAP`
3. Pass `regionAreas` to `getTodayOnSalePosts` when region is set but area is not
4. Render tier-1 region nav (全国 / 関東 / 関西) above existing area nav
5. Update `pageUrl()` to include `region` param when set
6. Update `generateMetadata` to handle `region` param

### Step 4 — `apps/web/app/oripa/oripa.module.css`

Add `.regionTabs` — visually distinct from `.areaTabs` (e.g., slightly larger font or different background) to make the hierarchy clear.

### Step 5 — Playwright verification

Screenshot at 390px and 1280px for each of: 全国, 関東, 関西, and 関東+秋葉原 states.
